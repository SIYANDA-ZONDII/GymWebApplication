UKZN SPORT - PASSWORD RESET SETUP
================================

Files changed
-------------
- GymWebApplication/Account/Forgot.aspx.cs: looks up each member in dbo.Member, generates a random six-digit code, stores only its SHA-256 hash, sends it to that member's registered email, and logs SMTP failures. Gmail SMTP tries port 587/STARTTLS first and falls back to port 465/SSL.
- GymWebApplication/Account/ResetPassword.aspx.cs: validates code and expiry, updates the login matching the member's registered email, and consumes the code in one transaction.
- GymWebApplication/Web.config: contains placeholders for secrets.
- PasswordReset.sql: creates PasswordReset if it does not exist.

REQUIRED CONFIGURATION (the application cannot send email until this is completed)
----------------------------------------------------------------------------------
1. In GymWebApplication/Web.config, replace YOUR_ROTATED_DATABASE_PASSWORD with your newly rotated SQL Server password. Do not share this file with secrets in it.
2. Set SmtpUsername and SmtpFromEmail to the Gmail account that sends reset messages. This is one sender account for all registered users; each recipient is read from dbo.Member.Member_Email.
3. Set SmtpPassword to a Google App Password for that Gmail account, not the normal Gmail password. Create it at https://myaccount.google.com/apppasswords after enabling 2-Step Verification.
4. Keep SmtpHost=smtp.gmail.com and SmtpPort=587. Code also attempts port 465 if the first SMTP mode fails.
5. Build in Visual Studio. In SQL Server Management Studio, select GroupWst23 and run PasswordReset.sql if dbo.PasswordReset does not already exist. The table must have Reset_ID, Member_ID, Reset_Code, Expiry_Date, Is_Used, and Created_Date columns.
6. Test using a real member record with a valid Member_Email and a Login.Username equal to that email.

IMPORTANT
---------
- The email sender credentials must be supplied by the project owner; no source code can send authenticated Gmail mail without valid sender credentials.
- The reset code expires after 10 minutes and can only be used once.
- This project currently compares passwords as plain text in the existing login implementation. The reset code intentionally preserves that existing format for compatibility. Before production deployment, migrate registration, login, and reset together to secure password hashing.
- SMTP failure details are written to Trace/Debug logs. Never show full exceptions or credentials to website users.
